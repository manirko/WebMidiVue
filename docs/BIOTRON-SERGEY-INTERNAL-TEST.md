## До теста

**Обязательный порядок: телефон Андрея → Сергей → клиентские gates.** До
передачи Сергею Андрей проходит физический mobile acceptance этого exact build
на своём телефоне. Полный результат **не закрыт**. 7 октября Андрей подтвердил
работающее подключение, а на отдельный вопрос явно ответил: «Да, калибровка
прошла и звук слышен». Среда: iPhone 16 Pro USB-C, его Web MIDI Browser,
временный exact D transport выше. Это reported first-sound PASS; точные версии
iOS/браузера и firmware readback ещё не записаны. Ответ не закрывает остальные
touch/fullscreen, reconnect/background, persistence/restore и phone firmware
guard checks; эти пункты остаются NOT RUN. Device viewport, успешный Mac,
Android-тест Сергея старой версии и предупреждение unsupported browser его не
заменяют. При FAIL / BLOCKED / NOT RUN карточку Сергею не передавать.

Оператор ведёт Андрея по одному шагу, фиксируя модель телефона, ОС,
браузер/версию, USB-переходник и firmware. Для Android — Chrome с USB/OTG; для
iPhone/iPad — отдельный экспериментальный MIDIWeb-путь. Обычный браузер без
необходимых возможностей проверяется как negative case, а не как успех USB.

Обязательные проверки на телефоне:

1. Открыть exact HTTPS preview и подключить настоящий Biotron: один рабочий
   MIDI endpoint, честный статус, версия/readback Settings; firmware не менять.
2. Start listening → подтверждённая калибровка → физически слышимый звук и
   реакция сенсоров. Нет вечного ожидания, щелчков и зависших нот.
3. Garden: touch/drag, полный экран, выход крестиком с первого нажатия;
   портрет/альбом, отсутствие перекрытых кнопок и горизонтального переполнения.
4. Stop/Start и Play↔Settings: корректная остановка/возврат звука без дублей.
5. Отсоединить/вернуть USB, затем увести приложение в фон/заблокировать телефон
   и вернуться: правдивый статус и восстановление MIDI/звука предложенным путём.
6. Экспорт baseline → один обратимый параметр → Save/replug/readback → вернуть
   baseline. Не терять исходные настройки; если сохранение заблокировано,
   остановиться на этом шаге.
7. Проверить, что firmware update недоступен на телефоне. Offline reopen и
   reduced motion фиксировать отдельно; обещать их поддержку только после
   физического PASS на этом browser/OS.

Результат привязать к exact runtime/firmware/среде; после затрагивающего mobile
исправления повторить неуспешный путь и соседние переходы. Непроверенный телефон
остаётся NOT RUN в QA runner, даже при всех зелёных software checks.

Зафиксировать текущую версию из Settings, board marker, ОС, браузер и версию Ableton. Не считать Fibonacci Андрея платой Сергея. При несовместимой/неизвестной плате прошивку не записывать. Если Play не получает firmware READY, сохранить точку остановки; не предлагать случайный UF2. Один Biotron, проверенный data-кабель. Экспорт baseline и recovery обязательны перед изменением настроек/прошиванием.

## Android — первое короткое задание

Интернет включён, firmware не меняется. Exact Play URL → подключить через USB/OTG → Start listening → дождаться калибровки → услышать звук. Один ответ: «звук есть» / «звука нет, остановился на …» / «не пробовал». Счётчики MIDI и AudioContext не заменяют физическую слышимость. Свободный комментарий о звучании приветствуется, обязательный технический отчёт не нужен.

## Windows/browser — проверки после первого звука

Почему нужен Сергей: настоящий Windows host и физический слышимый выход.

1. Закрыть DAW, открыть exact preview, подключить Biotron. Выбран один responsive MIDI port; версия читается. Нажать Start listening. Дождаться подтверждения калибровки, услышать звук.
2. Развернуть Garden, drag, закрыть крестиком, повторить с Escape после drag. Звук не обрывается; закрытие срабатывает с первого клика.
3. Stop & release: новых нот нет, хвост затихает. Повторный Start восстанавливает звук без дублей. Play→Settings→Play сохраняет звук одной сессии; Settings показывает «Sound stays on». Release device for DAW отдельно останавливает её.
4. Отключить USB во время звука, подключить обратно и восстановить сессию. Нет зависшей ноты; UI различает потерю устройства и отсутствие звука.
5. Изменить один обратимый параметр, сохранить, replug, проверить readback и восстановить baseline.

Оператор выдаёт эти проверки по одной. Первый reset, потеря USB, stuck note, непонятный статус — STOP; не продолжать ради общего PASS. Diagnostics/скриншот по необходимости; видео только если они не объясняют симптом. При отсутствии слышимого подтверждения звук BLOCKED, даже если MIDI counters растут.

## Ableton — реальная запись MIDI и возврат в веб

1. В Settings нажать **Release device for DAW**. Если порт остаётся занят, закрыть окна веб-приложения и записать необходимость этого действия. Затем открыть Ableton; интернет можно оставить включённым.
2. Settings/Preferences → **Link, Tempo & MIDI**: для основного Biotron **Input** включить **Track**. Служебный `MIDIIN2 (Biotron)` не выбирать вторым входом; не использовать `All Ins`. Для этой проверки не нужны Remote, Sync и отправка MIDI обратно в Biotron.
3. Новая MIDI-дорожка: **MIDI From → основной Biotron → All Channels**, **Monitor Auto**, **Arm**. Записать короткий MIDI-клип обычной записью Live, остановить запись и открыть клип. PASS — реальные ноты с длительностями в клипе, а не порт в списке или мигающий индикатор. Для прослушивания использовать уже имеющийся инструмент; не требовать новых плагинов.
4. Если ноты записались, но звука нет, разделить MIDI PASS и audio FAIL/BLOCKED. Остановка транспорта Live не обязана останавливать генеративный поток Biotron; это само по себе не stuck note.
5. Закрыть Ableton, вернуть устройство в Settings предложенным reconnect. Проверить readback и Play. Потребность в USB replug записать как наблюдение, не скрывать обещанием бесшовного возврата.

Один основной ответ: «ноты записались» / «не получилось, остановился на …» / «не пробовал». `.mid` просить только для разбора конкретного музыкального сбоя. Не обещаем совместное владение Windows-портом. При FAIL зафиксировать первое действие, версии и topology; не включать экспериментальные browser flags.

Настройка Track, выбор входа, Monitor и Arm сверены 2026-10-07 с [официальным routing manual Live 12](https://www.ableton.com/en/manual/routing-and-i-o/) и [записью MIDI-клипов](https://www.ableton.com/en/live-manual/12/recording-new-clips/). Название Settings/Preferences зависит от версии Live.

## Офлайн — отдельное задание

Сначала online load exact preview и явная offline-ready, затем предлагаемый ОС путь установки. Если кнопка недоступна, остановиться и описать экран; не обещать `.exe` и не применять Android-инструкцию к Windows. Лишь после готовности отключить сеть и открыть приложение снова. Отдельно проверить cached reopen и запуск после полного закрытия всех окон браузера/приложения. Повторить звук, вернуть сеть. Ableton не является условием офлайна; отказ файлового сервера на Mac не заменяет отключение сети Windows/Android.

## Прошивка → откат → повторная прошивка (отдельный допуск; сейчас BLOCKED)

Запускать только на подтверждённой совместимой плате с exact образами и проверенным восстановлением. Не совмещать со звуковыми/DAW заданиями. Browser updater сейчас не предлагает downgrade/reinstall текущей версии. Полная запись через directory picker и reconnect readback **этим runtime** на Windows ещё не доказаны. Native picotool PASS на Mac и Windows PASS beta24 от 8 сентября не закрывают этот пункт новой версии. Нельзя просить Сергея импровизировать обход или становиться первым recovery tester.

После внутреннего browser write и подтверждения платы: target → разрешённый rollback → тот же target, каждый переход с firmware readback, MIDI, калибровкой и сравнением настроек. Цикл остаётся обязательным; недоступный downgrade означает BLOCKED, а не PASS. Каждый проход выявляет лишние шаги, ручной диск, повторные разрешения и replug; упрощение сохраняет проверку образа и результата.

**Расхождение:** Сергей требовал factory reset при BOOT 10 сентября. Clean 1.10.9 сохраняет настройки (`firmware src/params.c`, commit `303aafc`). Требование не выполнено. Не обещать сброс и не вводить неожиданное стирание; отдельно решить семантику reset/recovery перед передачей этой карточки.
