# Biotron — простая проверка на Windows

Цель: проверить тестовые Settings, освобождение MIDI-порта для REAPER и offline
режим. Это изолированный тестовый комплект; он не меняет production-сайт.

## Перед началом

1. Подключите **только один Biotron** исправным USB data-кабелем.
2. Не обновляйте прошивку. Этот этап безопасно тестирует web/REAPER на уже
   установленной прошивке.
3. Сфотографируйте плату сверху и снизу, включая маркировку ревизии.
4. Установите Node.js LTS, Chrome или Edge и актуальный REAPER.
5. Закройте все приложения, которые могут использовать MIDI, включая другие
   вкладки Settings, Ableton и MIDI Monitor.

## Запуск

1. Распакуйте ZIP полностью в обычную папку, например `C:\BiotronTest`.
2. Дважды нажмите `START-BIOTRON-TEST.cmd`.
3. Введите имя, маркировку платы и текущую версию firmware. Если данных нет,
   напишите `UNKNOWN`, не угадывайте.
4. Не закрывайте чёрное окно. Chrome откроет
   `http://127.0.0.1:4173/#/biotron`.
5. Разрешите MIDI/SysEx только для этого localhost.

Если появилось предупреждение Windows Firewall, запретите доступ из публичных
сетей: сервер слушает только этот компьютер (`127.0.0.1`).

## Тест 1 — Settings

1. Страница должна показать один Biotron и его firmware version.
2. Сделайте скриншот.
3. Если устройства нет, версия не появляется или устройство внезапно вошло в
   `RPI-RP2`, остановитесь и запишите FAIL.

## Тест 2 — Settings → REAPER

1. Нажмите **Release device for DAW**.
2. Должно появиться сообщение, что выбранный порт свободен, без warning.
3. Только теперь откройте REAPER.
4. `Options → Preferences → Audio → MIDI Devices`.
5. В `MIDI inputs` включите Biotron (`Enable input`).
6. Создайте track, arm recording, выберите
   `Input: MIDI → Biotron → All channels`.
7. Подключите растение/коснитесь тестового контакта и запишите несколько MIDI
   событий. В track должна быть MIDI-активность.

## Тест 3 — честная ошибка и Reconnect

1. Пока REAPER ещё владеет Biotron, вернитесь в браузер и нажмите
   **Reconnect settings**.
2. Ожидается понятная ошибка. Settings не должны притворяться подключёнными.
3. В REAPER отключите Biotron или полностью закройте REAPER.
4. Нажмите **Reconnect settings** ещё раз.
5. Устройство и версия должны снова появиться без переподключения USB.
6. Повторите Release → REAPER → Reconnect пять раз. Для финального release-gate
   команда повторит 20 раз.

## Тест 4 — offline PWA

1. Закройте REAPER и убедитесь, что Settings снова подключены.
2. Подождите десять секунд, затем отключите Wi-Fi/Ethernet или включите режим
   полёта. Чёрное окно localhost оставьте открытым.
3. Обновите страницу, затем полностью закройте и снова откройте Chrome по адресу
   `http://127.0.0.1:4173/biotron`.
4. Biotron Settings должны открыться и перейти на `/#/biotron`.
5. Нажмите **Update Firmware**. Должно появиться сообщение, что для обновления
   нужен интернет; кнопка Update должна быть заблокирована.
6. Biotron не должен входить в `RPI-RP2`.
7. Верните сеть.

## Опционально — WinRT flag

Только после полного теста с настройкой по умолчанию:

1. Запишите версию Chrome.
2. Откройте `chrome://flags/#use-winrt-midi-api`.
3. Включите `Use Windows Runtime MIDI API`, перезапустите Chrome и повторите
   тесты 1–3.
4. Это отдельная диагностическая ячейка, а не доказанный fix REAPER-конфликта.

## Пока не делать

- Не копировать тестовую UF2 и не запускать burst CC — для этого будет второй
  комплект с pinned firmware artifact, SHA-256 и recovery-инструкцией.
- Не подключать два Biotron, пока один не прошёл тесты.
- Не замыкать неизвестные контакты и не угадывать ревизию платы.
- Не проверять на production Settings — используйте только localhost из ZIP.

## Что вернуть Андрею

В папке рядом с инструкцией появится `evidence-ДАТА-ВРЕМЯ`:

1. заполните `CHECKLIST.md` словами PASS / FAIL / BLOCKED;
2. положите туда скриншоты и короткое видео Release → REAPER → Reconnect;
3. заархивируйте папку целиком;
4. отдельно приложите фото платы сверху и снизу.

Любой FAIL важнее повторной попытки: сначала сохранить evidence, потом можно
повторить тест.
